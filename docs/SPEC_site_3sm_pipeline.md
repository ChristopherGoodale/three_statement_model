## 1. Objective

Build a reproducible Python pipeline that:

1. Retrieves SITE financial statement data from official SEC EDGAR sources.
2. Selects exactly one authoritative value per statement line per fiscal period, with full provenance.
3. Validates accounting identities in Python **before** anything is written to Google Sheets.
4. Renders a workbook where subtotals, checks, drivers, and the forecast model are **live formulas**.
5. Reads the sheet back and proves it matches what was intended.

The workbook supports a three-statement modeling curriculum. Week 1 is verified historicals, Week 2 is forecast drivers, and Week 3 is linkage and balancing.

## 2. Hard rules (non-negotiable)

| ID | Rule |
|---|---|
| **R1** | **No fabricated or hand-typed financial data.** No financial value may be typed into code, config, tests, docs, commit messages, gate-report prose, or the sheet. All financial values originate from SEC EDGAR responses cached under `data/raw/`. Reports *generated by code* from cached data may display values. |
| **R2** | **No invented XBRL concepts.** Concept mappings come from the filing's own linkbases (Phase 2 discovery) and require owner approval (`status: approved`) before the pipeline will use them. |
| **R3** | **Missing is not zero.** Never `fillna(0)` or otherwise default a missing fact. A missing required fact stops the run with an error naming the `line_id` and period. Lines legitimately absent in some periods must declare `allow_missing: true` and render blank. |
| **R4** | **No positional writes.** Every cell address comes from the layout registry (`line_id → row`, `period → column`). Rendering code contains no hardcoded A1 addresses. |
| **R5** | **No computed values pasted into the sheet.** Subtotals, checks, ratios, growth rates, and model lines are written as formulas. Python may compute the same quantities only for validation and verification. |
| **R6** | **Checks are formulas, never text.** No "✓" labels or static pass notes anywhere. |
| **R7** | **Validate before write; verify after write.** Nothing reaches the sheet unless Python validation passes. Nothing is "done" until read-back verification passes. |
| **R8** | **Credentials.** Read credential paths and identifiers from environment variables only. Never print, log, commit, or copy credential contents. |
| **R9** | **SEC fair access.** Send a declared User-Agent from env on every request, stay at or below the configured request rate (default 8/sec, under SEC's 10/sec limit), retry with exponential backoff, and cache to disk. Never re-fetch a cached response unless `--refresh` is passed. |
| **R10** | **Sheet safety.** Write only to the sheet ID selected by settings and flags. Modify only code-owned tabs and ranges. Never delete tabs, and never clear or overwrite human-owned cells. Develop against the scratch sheet; writing to production requires the explicit `--promote` flag. |
| **R11** | **Legacy artifacts are untrusted.** A prior port script wrote year-over-year growth rates into the FY2025 value column (a column-offset bug), and its "✓" checks were static text. Do not reuse its layout logic, and do not treat its xlsx or sheet as a data source or test oracle. |
| **R12** | **Scope control.** No new dependencies, tabs, features, or spec deviations without listing them in `PLAN.md` or a gate report for approval. |

**Test fixture policy (R1 corollary).**
- Unit tests may use synthetic fixtures only under `tests/fixtures/synthetic/`.
- Synthetic fixtures must be obviously artificial, must not imitate SITE's statements, must be documented as synthetic in `tests/fixtures/synthetic/README.md`, and must never be written to any Google Sheet.
- Integration tests use cached real SEC responses only.

## 3. Company-specific context (structural only; no values)

- **Issuer:** SiteOne Landscape Supply, Inc., CIK `0001650729`.
- **52/53-week fiscal year.** Never assume December 31 year-ends or 365-day periods. Derive period start, end, and days from XBRL fact contexts. The owner will confirm the fiscal-year convention from 10-K Note 1 before forecast period dates are generated.
- **Redeemable non-controlling interest (RNCI)** is presented in mezzanine equity, between total liabilities and stockholders' equity. Every balance check must include it.
- **Adjustment of RNCI to redemption value** appears in the path from net income to net income attributable to SiteOne. Equity and RNCI roll-forward components must be sourced from the Statement of Stockholders' Equity, never assumed.
- **Depreciation and amortization** is not a separate line on the income statement face. Source D&A lines from the cash flow statement.
- **Acquisitions** drive changes in goodwill and intangibles.
- **Custom (extension) tags.** Some lines may use company extension elements. SEC's XBRL APIs aggregate only facts using non-custom taxonomies (us-gaap, ifrs-full, dei, srt) that apply to the entire filing entity. Custom-tagged lines and dimensional facts (e.g., equity statement components) therefore will not appear in `companyfacts` and must come from instance-document parsing.

## 4. Scope

**In scope (v1):**
- Annual 10-K / 10-K/A data only.
- The three most recent fiscal years for the income statement, cash flow statement, and statement of stockholders' equity.
- Balance sheets at those three fiscal year-ends, plus the opening balance sheet at the prior year-end if `include_opening_balance_sheet: true`.
- Tabs: `README`, `Hist_IS`, `Hist_BS`, `Hist_CF`, `Hist_EQ`, `Sources`, `Checks`, `Assumptions`, `Model`.
- The anchor filing (most recent 10-K or 10-K/A) is discovered via the submissions API. **Do not hardcode filing dates, fiscal years, or accession numbers.**

**Out of scope (v1):** 10-Q ingestion, quarterly or LTM views, valuation (DCF, comps), charts, segment data, non-GAAP reconciliations, scheduling or automation of runs.

## 9. Pipeline stages: requirements and acceptance criteria

### 9.1 `edgar_client.py`

**Requirements**
- Read `SEC_USER_AGENT` from env and fail fast if it is missing.
- Throttle with a token bucket at `max_requests_per_second`.
- Retry with exponential backoff on HTTP 429 and 5xx. Fail after N attempts, where N comes from config.
- Maintain a disk cache keyed by URL hash, with a sidecar JSON holding `url`, `retrieved_at`, `status`, and `content_type`.
- Support a `--refresh` flag that bypasses the cache.
- Endpoints:
  - Submissions: `https://data.sec.gov/submissions/CIK{cik10}.json`
  - Company facts: `https://data.sec.gov/api/xbrl/companyfacts/CIK{cik10}.json`
  - Filing directory index: `https://www.sec.gov/Archives/edgar/data/{cik_int}/{accn_nodash}/index.json`, plus the files it lists (instance document and linkbases).

**Acceptance**
- Unit tests cover the throttle, backoff, cache hit/miss, and the missing-User-Agent failure.
- Unit tests make no network calls.
- The Gate 1 report confirms each endpoint behaved as expected, or documents deviations.

### 9.2 `extract.py`

**Requirements**
- **Filing discovery:** from the submissions API, find the anchor (latest 10-K or 10-K/A). Add the earlier 10-Ks required to cover every in-scope balance sheet date, including the opening balance sheet if enabled.
- **Standard facts:** normalize `companyfacts` into `facts_long`, with `source = companyfacts` and `dimensions = {}`.
- **Instance facts:** for each in-scope filing, parse the XBRL instance for:
  - facts whose concept is custom;
  - dimensional facts needed by `Hist_EQ`;
  - any required line absent from `companyfacts`.
  Set `source = instance`.
- Never key or filter by the `fy` / `fp` fields. They describe the filing, not the period a fact covers.

**Acceptance**
- `facts_long` has no duplicate rows on the full key.
- Every row has `accn` and `raw_path`.
- A generated summary reports fact counts by source, form, and filing.

### 9.3 `discovery.py` (Phase 2)

**Requirements**
- **Parser spike:** evaluate the candidate parsers on the anchor filing against these criteria: correct identification of the primary statement roles, dimension handling, label and negated-label roles, calculation weights, license, install footprint, and maintenance activity. Recommend one parser.
- **Presentation linkbase:** enumerate the four primary statements (IS, BS, CF, Stockholders' Equity). For each line, capture presentation order, preferred label, concept, taxonomy type, dimensional context, negated-label role, and whether the concept is present in `companyfacts`.
- **Calculation linkbase:** extract parent/child relationships and weights, then propose `formula` templates and `sign` values.
- **Outputs:**
  - `reports/concept_discovery_{accn_nodash}_{YYYYMMDD}.md`
  - a draft `config/line_items.yaml` with every entry `status: proposed`
  - proposed `checks` in `config/templates.yaml`

**Acceptance**
- Every line on the face of the four primary statements appears in the discovery report.
- Any line that could not be mapped is listed explicitly with the reason.
- No concept appears in the draft config that was not found in the filing.

### 9.4 `select_facts.py`

**Requirements**
- Keep forms `10-K` and `10-K/A` only.
- Instants pass. Durations pass only if inclusive `days` is between 357 and 378, which accommodates 52-week (364-day) and 53-week (371-day) fiscal years.
- Selection key: `(concept, unit, dimensions, start, end)`.
- Write `recasts.parquet` **before** deduplication.
- Resolution rule: the most recently filed value wins.
- Map facts to `line_id` using each line's ordered `concepts` fallback list, `dimensions`, and `unit`.
- Enforce exactly one value per `(line_id, period_end)`. Zero matches for a required line is an error (R3). More than one surviving match is an error.
- Apply `sign`, recording it in `sign_applied`.

**Acceptance (unit tests on synthetic fixtures)**
- Annual/quarterly duration filtering is correct, including 364- and 371-day periods.
- A fact reported in multiple filings resolves to the latest filed value and is logged in recasts.
- A missing required fact raises; an allowed-missing fact yields no row, never a zero.
- Concept fallback order is respected.
- Dimensional and non-dimensional facts for the same concept are never conflated.
- Selection never reads `fy` or `fp`.

### 9.5 `validate.py`

**Requirements**

Run on the curated frame, computing in Python from facts and approved templates:
1. **Subtotals:** every `formula` line with `reported_concepts` matches the reported value within tolerance.
2. **Balance sheet:** total assets equals total liabilities + RNCI + total stockholders' equity, at every balance sheet date.
3. **Cash flow arithmetic:** operating + investing + financing + FX effect (plus any other reconciling lines present in the filing) equals the net change in cash.
4. **Cash roll:** beginning cash plus net change equals ending cash.
5. **Cash continuity:** CF beginning cash(t) equals CF ending cash(t−1), where both periods exist.
6. **Cash tie:** CF ending cash equals BS cash, using the `cash_tie` line IDs from settings.
7. **Net income tie:** consolidated net income on the IS equals the starting net income on the CF.
8. **Retained earnings roll-forward:** built from approved `Hist_EQ` components.
9. **RNCI roll-forward:** built from approved `Hist_EQ` components.
10. **Magnitude guard:** any nonzero USD value with absolute unscaled value below `usd_magnitude_guard` fails.
11. **Unit guard:** a line's selected fact unit must match its configured `unit`.

**Outputs:** `reports/validation_{YYYYMMDD}.md`, listing each check by period with pass/fail and difference. Any failure exits non-zero, and rendering does not run.

**Acceptance**
- Each identity has a unit test with a synthetic passing case and a synthetic failing case.
- The magnitude guard test confirms that a ratio-sized value in a USD line fails. This is the legacy bug.

### 9.6 `layout.py` and `formulas.py`

**Global period axis.** The same period uses the same column letter on every period-based tab (`Hist_*`, `Assumptions`, `Model`).

```
Col A  label
Col B  line_id
Col C  unit
Col D  flag (ACQ | RNCI | D&A | 53WK | blank)
Col E  opening balance sheet date (BS/EQ only; blank on IS/CF)
Col F  historical FY-2
Col G  historical FY-1
Col H  historical FY0 (anchor)
Col I+ forecast FY+1 … FY+N (Model/Assumptions only)
```

If `include_opening_balance_sheet` is false, column E stays reserved but empty, so column letters never shift.

**Header rows** (identical on every period-based tab): `HDR_FISCAL_YEAR_LABEL`, `HDR_PERIOD_START`, `HDR_PERIOD_END`, `HDR_DAYS` (a formula: `=HDR_PERIOD_END - HDR_PERIOD_START + 1`, consistent with the inclusive convention in 7.1; forecast `HDR_PERIOD_START` = prior `HDR_PERIOD_END` + 1), and `HDR_AE_FLAG` (A or E).

**Row assignment.** Rows follow `order` and `section` from config, with deterministic spacing. Two lines may never share a row.

**Template token grammar**

| Token | Resolves to |
|---|---|
| `{LINE_ID}` | Same tab, same period column |
| `{TAB!LINE_ID}` | Other tab, same period column, sheet-quoted |
| `{LINE_ID@prev}` / `{TAB!LINE_ID@prev}` | Prior period column |
| `{TAB!LINE_ID@abs}` | Absolute reference to a `kind: scalar` single cell (e.g. the tolerance input) |

**Resolver errors (all must raise):** unknown `line_id`; unknown tab; `@prev` with no prior period; `@abs` on a non-scalar; any unresolved `{` or `}` left after substitution.

**Collision guard.** Build the complete write set as `(tab, a1) → value | formula` before any API call. Any duplicate target raises.

**Acceptance**
- Tests cover the column mapping (period order ascending, unique, stable across tabs), every token form, every error case, and a collision test that reproduces the legacy offset pattern and raises.

### 9.7 `sheets_writer.py`

**Requirements**
- Authenticate as the service account using the path in `GOOGLE_APPLICATION_CREDENTIALS`.
- Select the target sheet: `SHEET_ID_SCRATCH` by default, `SHEET_ID_PROD` only with `--promote`.
- Create missing code-owned tabs. Never delete tabs.
- Clear only code-owned ranges. Human-owned ranges are never read-modify-written.
- Write in batches grouped by tab, with `value_input_option="USER_ENTERED"`. `RAW` would store formulas as literal text.
- Derive formatting from cell kind, never assign it manually:

| Cell kind | Formatting |
|---|---|
| `fact` | Blue font |
| Same-tab formula | Black font |
| Cross-tab formula | Green font |
| Human input | Yellow fill; value left blank |
| `header` | Bold |

- Apply number formats by unit from settings, and freeze the header rows and columns A–D.
- `--dry-run` writes the complete planned write set to `reports/render_plan_{YYYYMMDD}.csv` (`tab, a1, kind, value_or_formula, owner`) and makes no API calls.

**Acceptance**
- Dry-run output is deterministic across repeated runs.
- A unit test confirms that human-owned cells are excluded from both the clear ranges and the write set.

### 9.8 `verify.py`

**Requirements.** Read back every code-owned range with `value_render_option="UNFORMATTED_VALUE"` and with `"FORMULA"`, then assert:
1. Every `fact` cell equals the curated `value / display_scale`, within float epsilon.
2. Every formula cell begins with `=`, and its text equals the intended resolved formula.
3. Every check status cell reads `OK`, and `CHK_MASTER` reads `OK`.
4. No unexpected non-empty cells exist inside code-owned ranges.

**Outputs:** `reports/verify_{YYYYMMDD}.md`. Any failure exits non-zero.

### 9.9 `run.py` (CLI)


|---|---|---|
| `README` | Code | Model purpose, units, color key, last run ID, target sheet, and a link cell to `CHK_MASTER` |
| `Hist_IS` | Code | Fact inputs plus subtotal formulas; memo rows for D&A (linked from `Hist_CF`, not re-entered) |
| `Hist_BS` | Code | Fact inputs plus subtotal formulas; RNCI as its own block between liabilities and equity |
| `Hist_CF` | Code | Fact inputs plus subtotal formulas; beginning cash for FY-1 onward is a formula linking to the prior period's ending cash; FY-2 beginning cash is a fact |
| `Hist_EQ` | Code | Statement of stockholders' equity components required for the retained earnings and RNCI roll-forwards (dimensional facts) |
| `Sources` | Code | One row per curated fact (Section 10.4) |
| `Checks` | Code | `CHK_TOLERANCE` scalar input, check difference rows, status rows, `CHK_MASTER` |
| `Assumptions` | Mixed | Historical driver formulas (code); forecast input cells (human, yellow fill, blank) |
| `Model` | Code | Historical columns as green links to `Hist_*`; forecast columns from approved templates |

**Single-entry rule.** Every fact is written exactly once, on its home `Hist_*` tab. Any other appearance must be a link formula.

### 10.2 Checks

Each check occupies a pair of rows: a difference row `CHK_<NAME>`, and a status row `CHK_<NAME>_STATUS` with the formula `=IF(ABS(<diff>)<={Checks!CHK_TOLERANCE@abs},"OK","CHECK")`. Blank periods (e.g., no prior period) render blank, not `OK`.

| Check ID | Tests |
|---|---|
| `CHK_TOLERANCE` | Scalar input written from `settings.validation.tolerance_usd_millions` |
| `CHK_SUBTOTAL_<LINE_ID>` | One per formula line with `reported_concepts`: formula value minus reported value |
| `CHK_BS_BALANCE` | Assets − (liabilities + RNCI + stockholders' equity) |
| `CHK_CF_NET_CHANGE` | Sum of section totals and reconciling lines − net change in cash |
| `CHK_CF_CASH_ROLL` | Beginning cash + net change − ending cash |
| `CHK_CF_CASH_CONTINUITY` | Beginning cash(t) − ending cash(t−1) |
| `CHK_CASH_TIE` | CF ending cash − BS cash (line IDs from `settings.cash_tie`) |
| `CHK_NI_TIE` | IS consolidated net income − CF net income |
| `CHK_RE_ROLLFORWARD` | Prior retained earnings + approved EQ components − current retained earnings |
| `CHK_RNCI_ROLLFORWARD` | Prior RNCI + approved EQ components − current RNCI |
| `CHK_INPUTS_COMPLETE` | Count of blank human forecast input cells (status `OK` only when 0; applies from Phase 7) |
| `CHK_MODEL_BS_BALANCE` | Forecast balance sheet balance (Phase 7) |
| `CHK_MODEL_CASH_TIE` | Forecast CF ending cash − forecast BS cash (Phase 7) |
| `CHK_MASTER` | `OK` only if the count of `CHECK` across all status rows is 0; otherwise `FAILURES: n` |

Roll-forward components are defined in `templates.yaml` from approved `Hist_EQ` line IDs. **Do not assume which components exist.** Discovery determines them from the equity statement.

### 10.3 Assumptions

**Historical driver block** (code-written formulas; the owner approves the final list in `templates.yaml`). Initial proposal:

| Driver ID | Definition |
|---|---|
| `AS_SALES_GROWTH` | Net sales / prior net sales − 1 |
| `AS_GROSS_MARGIN` | Gross profit / net sales |
| `AS_SGA_PCT_SALES` | SG&A / net sales (note: includes D&A) |
| `AS_OTHER_INCOME_PCT_SALES` | Other income / net sales |
| `AS_TAX_RATE` | Income tax expense / pre-tax income |
| `AS_DSO` | Receivables / net sales × `HDR_DAYS` |
| `AS_DIO` | Inventory / COGS × `HDR_DAYS` |
| `AS_DPO` | Payables / COGS × `HDR_DAYS` |
| `AS_CAPEX_PCT_SALES` | Capex (as outflow magnitude) / net sales |
| `AS_DEPR_PCT_BEG_PPE` | Depreciation / prior-period PP&E |
| `AS_INTEREST_RATE_BEG_DEBT` | Interest expense / prior-period debt (debt definition is an owner decision) |
| `AS_NCI_SHARE_NI` | NI attributable to NCI / consolidated net income |
| `AS_SBC_PCT_SALES` | Stock-based compensation / net sales |

- Guard every division so that a zero or blank denominator returns blank, not an error.
- Driver formulas for the FY-2 column that require a prior period render blank.
- **Forecast input block:** one human-owned input row per driver (`AS_IN_<NAME>`) in the forecast columns, with yellow fill, **left blank by code** (R1). The owner enters inputs manually.

### 10.4 Sources

Columns: `line_id | tab | label | period_end | value_as_filed_unscaled | unit | concept | taxonomy_type | dimensions | accn | form | filed | source | recast_flag | raw_path`

These values are rendered directly from `historicals.parquet`; they are never typed.

### 10.5 Model (Phase 7)

- Historical columns F:H are green link formulas to `Hist_*`, so `@prev` works uniformly for the first forecast year.
- Forecast column templates come only from approved `templates.yaml` `model` entries.
- **Linkage order:** IS → working capital schedule → PP&E schedule → goodwill and intangibles → debt schedule → equity and RNCI roll-forwards → BS → CF (derived from IS and BS changes) → ending cash to BS → model checks.
- **Interest** is calculated on beginning-of-period debt in v1, so there are no circular references and no iterative calculation.
- **No plugs.** Any template that forces balance (e.g., cash or any balance sheet line set as total L&E minus other assets) is prohibited. The balance sheet must balance through the linkages.
- **Forecast period dates** come from `settings.periods.fiscal_year_rule`. If it is null, Phase 7 rendering refuses to run.

## 12. Planning and reporting formats

### 12.1 `PLAN.md` structure

1. **Objective restated** (10 lines or fewer).
